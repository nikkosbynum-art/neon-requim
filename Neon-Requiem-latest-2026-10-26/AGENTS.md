# Instructions for Codex sessions

Before changing systems, read `docs/DESIGN_DECISIONS.md` and `docs/IMPLEMENTATION_STATUS.md`. Before changing game design or BREAKER presentation, also read `migration_package/README_START_HERE.md`, `migration_package/AGENTS.md`, `migration_package/docs/DECISION_STATUS.md`, all `migration_package/notion_reconstruction/*.md`, and `migration_package/drive_assets/Breaker_Tier1_Godot_Production_Spec.md`. That package is an offline reconstructed handoff, not a verbatim Notion export. Check linked canonical sources in `docs/MIGRATION_REPORT.md` when access is available; do not fill gaps with guesses.

Before generating or extracting modular character artwork, read `docs/CHARACTER_PART_AUTHORING_GUIDE.md`, the approved per-character visual reference, and the approved anatomy turnaround. A transparent atlas or successful alpha segmentation does not prove that parts are complete, correctly labeled, unique, or rig-compatible. Keep candidates quarantined until the guide's visual and semantic gates pass.

Preserve approved decisions and existing project history. Do not replace the project wholesale, remove assets, or overwrite established code without authorization. The code-drawn character/enemy visuals and the numeric combat/economy values are prototype placeholders, not canon. The PNG concept sheets in `migration_package/drive_assets/concept_art/` are reference art, not animation-ready sprite parts; do not put them into runtime character scenes. Keep combat simulation authoritative and separate from presentation. Do not add gacha, manual targeting, or player-triggered abilities. Modular encounter zones with seamless-looking transitions were explicitly approved by the user on 2026-10-24; current Undercity palette modules and their wave-13 test boundary are provisional presentation fixtures, not canonical location content or pacing.

Update `docs/IMPLEMENTATION_STATUS.md`, `docs/ASSET_MANIFEST.md`, and `docs/MIGRATION_REPORT.md` when implementation or source access changes. Record validation only after running it. Do not check in `.godot/`, generated caches, credentials, user saves, or unnecessary binaries.

Before running the full Python regression suite, use `python tests/run_python_tests.py`. It preflights the project-local fixture directories used by the tests and stops before test discovery if writes are blocked. A `BLOCKED` preflight is an environment permission issue, not a code regression; rerun only with approved test-write access to the project paths it lists. Do not report errors from an unapproved/read-only run as test failures. If a new test uses `tempfile.TemporaryDirectory(dir=...)` under another project directory, add that parent to `FIXTURE_WRITE_DIRS` in the runner.

While Notion/Drive connectors are unavailable, use the offline handoff and current local project documentation as the working source, with their reconstructed/noncanonical status kept explicit. Record deferred remote reconciliation and uploads in `docs/REMOTE_SYNC_QUEUE.md`; refresh the labeled local `Notion/` and `Google Drive/` staging copies as work changes. Do not claim a remote read, update, or upload until it succeeds and is verified. When access returns, reconcile against the live canonical sources, then process the queued changes together and record remote readback evidence.
