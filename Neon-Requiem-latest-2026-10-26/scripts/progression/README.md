# Progression and economy

`economy.gd` owns prototype run credits, deterministic upgrade costs/purchases, recruit run-levels, and run save data. `progression_rules.gd` provides pure, data-driven primitives for Reboot Influence awards, the prototype-trial lifetime power bonus, milestone-plus-material evolution gates, material consumption, and one-time first-clear claims. `evolution_service.gd` records a per-recruit tier transaction for all twelve approved roster IDs. `scripts/main.gd` exposes those transactions in a roster-wide Evolution panel and saves the permanent tier plus current run before applying live state. The established `breaker_tier` save key is preserved; other recruits use their recruit ID plus `_tier`. These transactions record progression only: tier stat/trait effects and higher-tier art are not implemented. The material gates and rewards in `data/progression/progression_prototype_profile.json` are approved for prototype feasibility testing only, not final balance or canon. System Reboot, wave-clear material rewards, offline credit claims, and permanent damage-bonus application are also integrated; the four-branch research UI remains read-only with an empty catalog pending approved node values. See `docs/PROGRESSION_RULES_PROPOSAL.md`.
